# v2.13.3 发布验证修复

v2.13.2 已上线，但其局部 36 项回归并不代表完整发布门通过。原 GitHub Actions `37566285868` 在 lint 退出，`37566285835` 在完整 E2E 尚未完成时取消；此记录不能作为发布验收成功证据。

## 修复范围

- 将测试中的宽泛 Function 类型改为明确函数签名，保持 lint 规则。
- 测试统一使用明确的 PLAYWRIGHT_BASE_URL。默认运行器构建后启动生产服务器，不复用未知服务；显式地址不可用时拒绝回退。
- 两条 CI 工作流均保留桌面和手机的全部测试，分为四片，失败不取消其他片，不使用重试掩盖失败；上传 HTML、JSON 和失败附件。
- 补齐状态机命令与家长密码、直接答题模式单测。旧测试通过真实家长密码 UI 解锁；适配已确认的星星清零规则和当前反馈，保留单次提交、真实记录、完整六题、奖励不重复等业务断言。
- 进阶题明确使用直接答题模式，不把答案句作为题意选项。新课程和缓存课程均跳过不可用的题意选择；传统选择模式仍要求至少两个唯一选项、唯一正确项。
- 修复 G1 比较题与图形题分类、乘除越级题和部分未出现在题干中的派生数字线索；保留原防泄题检查。
- 完成课程时把奖励兼容标记、课程恢复快照与积分账本纳入同一事务；回归检查完成只奖励一次，刷新后账本不变。

## 完整验收口径

保留原有 240 项 E2E，新增 6 项缓存题意流程检查，共 246 项（桌面和手机）。不得出现 failed、skipped、interrupted，retries 为 0。局部诊断报告用于定位，不累加为完整通过。

本地运行：

```powershell
npm run validate:release
```

运行器会为本地 E2E 构建并启动 127.0.0.1:3100。该端口已有服务时拒绝运行；需要测试另一个已启动的生产服务器时，显式设置 PLAYWRIGHT_BASE_URL。

最终发布要求同一 Git 提交的 E2E 与 Validate Release 两条工作流均成功。浏览器密码仍只保存在当前设备的当前浏览器，不提供云端同步。
